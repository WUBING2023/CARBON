## 1. 核心科学问题

真实 eCLIP binding peak 及其局部核心区域，是否比同任务（同一 RBP、同一 cell line 的 ENCODE task）中的非 peak 区域更保守？

---

## 2. 要验证的具体假设

在同一 task 内，observed peak / high-signal region 的 PhyloP 分数高于 matched non-peak regions；并且这种富集在 peak summit 附近更明显。

---

## 3. 所需输入数据

- **observed eCLIP signal**：与训练/评估一致的碱基分辨率 profile。  
- **peak 定义规则**：与论文 Methods 中 peak-level 评估一致或可复现的替代规则（见第 4 节与仓库 `find_peaks`）。  
- **PhyloP per-base scores**：窗内可直接用 HDF5 第 5 通道；窗外或重centering 时用项目内 bigWig（见第 4 节）。  
- **sequence / GC content**：可由 one-hot 通道计算 GC（或转录本上下文，若后续接入注释）。  
- **可选**：转录本区域注释（5′UTR / CDS / 3′UTR / intron）、gene ID；**control signal** 在本仓库中为 `Y_ctl`，建议纳入 matched 对照的协变量或匹配维度。

### 4.2 test 样本筛选（与数据处理与 Figure4 一致）

- **测试染色体**：数据处理管线中 `test_chr` 为 **chr1、chr8、chr15**（见 [`数据处理/Archive 4/自动化处理脚本/重要参数说明.md`](/data/CARBON_PROJECT/数据处理/Archive 4/自动化处理脚本/重要参数说明.md)）。本实验分析 test 集时，应**仅使用**上述染色体对应的 `{task}_chr1|8|15_*.h5` 与元数据文件，避免训练/验证泄漏。  
- **BED 过滤（可选但与 Figure4 同源）**：测试区间 key 集合来自 `/data/CARBON_PROJECT/数据/new_beddata/` 下对应 BED（至少 6 列：`chrom`, `start`, `end`, …, `strand`）。逻辑等价于 `read_test_bed_keys(bed_path)`：规范化染色体名后与 `df` 中 `(chr, chromStart, chromEnd, strand)` 做集合匹配，只保留属于 test BED 的行（见 [`图/figure4/figure4_locus_utils.py`](/data/CARBON_PROJECT/图/figure4/figure4_locus_utils.py)）。  

若不使用 BED 子集，则退化为「test 染色体上全部窗口」，需在文中明确。

### 4.3 observed peak 定义与 MARCP `find_peaks`

仓库实现：[`MARCP/MARCP/utils/functions.py`](/data/CARBON_PROJECT/MARCP/MARCP/utils/functions.py) 中 `find_peaks(signal_list, signal_max_threshold=2, signal_sum_threshold=4, signal_length=1)`。

**语义（与论文审计 [`论文/find_peaks检查.md`](/data/CARBON_PROJECT/论文/find_peaks检查.md) 方向一致）**

1. 将 `Y` 视为长度 101 的浮点列表；**连续非零**片段视为候选段（片段间以 0 分隔）。  
2. 对每一段，若长度 ≥ `signal_length`（默认 1），且 **（段内 max ≥ `signal_max_threshold`）或（段内 sum ≥ `signal_sum_threshold`）**，则将该段**内所有碱基位置**标为 peak 标签 1；否则为 0。  
3. 默认阈值：**max ≥ 2 或 sum ≥ 4**。

**与训练指标代码的差异（必须在 Methods 中二选一或并列报告）**

- [`MARCP/MARCP/operations/train_ops.py`](/data/CARBON_PROJECT/MARCP/MARCP/operations/train_ops.py) 中 `calculate_batch_metrics_seq`：对每个样本的 `row_target` 调用 **`find_peaks(row_target)`**，即 **2 / 4**（默认）。  
- 同文件 `calculate_batch_metrics_whole`：将 **整 batch 的 `targets` flatten 成一维** 后再调用 `find_peaks(..., signal_max_threshold=2, signal_sum_threshold=2)`。该口径跨样本边界连接，**不等价**于「单窗 peak」生物学解释。  

**本实验推荐**：在每个 **101 bp 窗口**内，对 **`Y` 单独**调用与默认 `find_peaks` 一致的 **signal_max_threshold=2、signal_sum_threshold=4**，得到窗内 peak 二值掩码；再在该掩码为 1 的区域上汇总 PhyloP。这与 **逐窗 Peak AUC** 使用的 peak 标签构造一致。敏感性分析可并列报告 **sum 阈值改为 2**（对齐 `whole` 中的数值，但仍建议勿 flatten 跨窗）。

**窗内 summit（用于 metaplot 对齐）**：在整段 `Y` 上取 **`argmax(Y)`** 作为该窗 binding summit 的索引（与 `figure4_locus_utils` 中在未提供 `summit_profile` 时以 eCLIP 定峰顶的做法一致）；若 `find_peaks` 在该窗无 peak，该窗可标记为「无峰」并在敏感性分析中剔除或单独分层。

### 4.4 两档实现策略（Tier A / Tier B）

| 档位 | 数据 | PhyloP 来源 | 适用场景 |
|------|------|-------------|----------|
| **Tier A（推荐先做）** | 仅 `_5ch` 的 `X`, `Y`, `Y_ctl` + 元数据 `df` | **`X[..., 4]`** | peak core、summit±k、flank 均在 **101 bp 窗内**定义；子区间不得越出 `[0,100]`（越界则截断或记 NA）。无需 pyBigWig。 |
| **Tier B（补充）** | 同上 + 基因组 FASTA / PhyloP bigWig | **`/data/CARBON_PROJECT/数据/phyloP/hg38.phyloP100way.bw`**（与 [`图/figure4/figure4_locus_plotting.py`](/data/CARBON_PROJECT/图/figure4/figure4_locus_plotting.py) 默认一致） | 需要 **超出 101 bp** 的 flank、以基因组绝对坐标重centering、或与 `extract_101bp_recenter_on_genomic_peak` 同流程重截窗时。依赖 `pysam`、`pyBigWig`，链型与坐标换算遵循 `figure4_locus_utils`。 |

**matched non-peak**：在同一窗内，于 **非 peak 掩码位置** 中选取与 peak 段 **等长** 或等总 signal 的区间；或从「无峰窗口」池中按 GC / 总 signal / `Y_ctl` 总和做最近邻匹配（见第 5 节）。Tier A 下 GC 可由 `X[...,0:4]` 在候选区间上计算。

## 5. 具体分析设计

### 5.1 样本构建

- 在 **test windows** 上，使用第 4.3 节与仓库一致的 **`find_peaks(Y)`** 生成窗内 peak 区间（连续 1 掩码段）；不另起一套互斥规则，除非做敏感性分析。  
- 对每个 peak 段（若一窗多段则每段一行）提取：  
  - peak mean / max PhyloP（Tier A：`X[...,4]` 在掩码为 1 的位置）；  
  - summit ±5 / ±10 nt 的 mean PhyloP（summit 为 `argmax(Y)` 的索引，子区间在 `[0,100]` 内截断）；  
  - flank：例如 peak 段两侧各 20 nt（若一侧越界则只取窗内可用部分或记为缺失并在 QC 中统计比例）。  
- 为每个 peak 段匹配 **1–5** 个 non-peak control，优先控制：  
  - 同一 task；  
  - 同一染色体（test chr 子集内）；  
  - 相近 GC、相近窗口总 signal 或 **control（`Y_ctl`）总和**；  
  - 若接入注释：再控制 transcript region / same gene。  

### 5.2 正例与对照

- **正例**：peak core（掩码为 1 的区段）或高 signal 子段。  
- **对照 1**：matched non-peak windows 或窗内 matched 非峰区间。  
- **对照 2**：同一 peak 的 flanking regions（窗内 peak 外侧）。  

同时得到 **between-region** 与 **within-window** 对照。

### 5.3 比较对象

- peak vs matched non-peak  
- summit-centered meta-profile vs random centers（随机置换 summit 索引或打乱 PhyloP 相对 summit 的偏移，作 null）  
- peak core vs peak flanks

## 6. 实现流程（与 Tier 对齐）

1. **枚举 task**：与全量实验一致（例如约 222 个 task）；task 列表可与 [`论文/Results.md`](/data/CARBON_PROJECT/论文/Results.md) 中汇总表对齐以便叙述。  
2. **读取 test**：对每个 task，仅打开 chr **1 / 8 / 15** 的 `_5ch` 与对应元数据 `df`；可选应用 `read_test_bed_keys` 子集。  
3. **逐行加载** `Y`, `Y_ctl`, `X`；对 `Y` 调用 **窗内** `find_peaks`（默认 2/4），得到 peak 掩码与段边界。  
4. **Tier A**：由 `X[...,4]` 与掩码计算 core / flank / summit 邻域统计量；由 one-hot 计算 GC 及候选对照区间。  
5. **Tier B（可选）**：对需外扩的区间，用 `chromStart/chromEnd/strand` 换算基因组坐标，用 `hg38.phyloP100way.bw` 取 per-base 值（链型处理同 `figure4_locus_utils`）。  
6. **pandas** 汇总为 `peak_table`（第 13 节）；按 task 输出效应量，再跨 task 汇总。  
7. **作图**：分布图 + summit-centered metaplot（Tier A 下 center 为 `argmax(Y)`，x 轴为相对 summit 的偏移，范围受 101 限制；若需 ±25 nt 全窗覆盖，保证 summit 距窗缘至少 25 nt 或在 Tier B 重截 101 bp 使 summit 居中）。  

**说明**：原稿中「pyBigWig 提取 peak 内及 flank」在 **Tier A** 下改为优先 **`X[...,4]`**；pyBigWig 作为 **Tier B** 或外扩 flank 时使用。

## 7. 统计检验、效应量与多重比较

### 7.1 Task 内

- **paired Wilcoxon signed-rank**：同一 peak 与其 matched control（或 core vs flank）的配对比较。  
- **效应量**：median difference、rank-biserial correlation 等。  
- **可选**：logistic 回归 `is_peak ~ mean_phyloP + GC + region_type + control_signal`（注意与因果方向表述区分）。  

### 7.2 跨 task

对每个 task 定义 **enrichment score**，例如：  
**ΔphyloP = mean(peak_core) − mean(matched_nonpeak)**（或中位数差）。

再对全部 task：

- 对 ΔphyloP 做 **Wilcoxon signed-rank against 0**（或 one-sample 符号检验）；  
- 报告 **fraction of tasks with ΔphyloP > 0**；  
- **K562 / HepG2**（或你文中使用的 cell line 分层）分别重复上述步骤。  

### 7.3 多重比较与异质性

- **222 个 task 等价于 222 次假设**时，若对每 task 报告 p 值，需说明 **FDR（Benjamini–Hochberg）** 或仅将 per-task p 作探索性、主结论依赖 **跨 task 的符号合并 / Stouffer / 分层图**。  
- 主文建议强调 **效应分布与细胞系分层**，避免单 task p 值钓鱼；补充材料可给每 task 的 ΔphyloP heatmap（见第 14 节）。

## 8. 预期可能出现的结果模式

**支持假设时**

- peak core 的 PhyloP 分布相对 matched control **整体右移**；  
- summit-centered metaplot 在中心有明显抬升；  
- 多数 task 的 ΔphyloP > 0。  

**不支持或弱支持时**

- peak 与 matched control 分布接近；  
- 仅 **部分 RBP** 有富集；  
- 中心无 metaplot 抬升。  

---

## 9. 可解释性与论文价值

这是最标准的 **biological plausibility** 证据：说明保守性通道所携带的信号并非随意拼接，而是在 **真实 binding regions** 上相对匹配背景具有统计富集，从而支撑模型设计与生物学叙事的一致性。

## 10. 风险、局限与缓解（含与数据结构一致的对照）

| 风险 | 缓解（与本仓库一致处已标注） |
|------|------------------------------|
| peak 更可能位于 exon/UTR，整体更保守 | matched background；分层 **region_type**（若注释可用） |
| GC 与转录本上下文混淆 | matching 中加入 **GC**（由 `X` one-hot 计算）；可选 **gene / 区域类型** |
| 部分 RBP 偏好低保守或 repeat 区 | 报告异质性；分家族 / cell line 展示 |
| eCLIP 阈值影响 peak | **敏感性分析**：`find_peaks` 的 sum 阈值 4 vs 2；剔除无峰窗 |
| 窗长仅 101 bp，flank 物理空间受限 | **Tier B** 外扩；文中明确「窗内 flank」与「基因组 flank」两种口径 |

**与数据结构自然一致的对照**

- **同一 task、同一链型、同一 test 染色体**：由数据行天然保证。  
- **control signal**：使用 **`Y_ctl`** 的窗口总和或 profile 特征参与 matching 或回归，与 MARCP 数据管线一致。

## 13. peak_table 字段与计算定义

以下为逻辑表字段；落地时为 CSV / Parquet 等均可。

| 字段 | 计算定义 |
|------|----------|
| `task_id` | ENCODE 任务目录名，与 `h5data/<task_id>/` 一致。 |
| `rbp` | 从 `task_id` 解析（例如前缀到第一个 `_HepG2`/`_K562` 或与项目命名规则一致）；若已有映射表则 join。 |
| `cell_line` | 从 `task_id` 解析（如 `HepG2` / `K562`）；与 [`论文/Results.md`](/data/CARBON_PROJECT/论文/Results.md) 中 cell line 表述保持一致。 |
| `peak_id` | 建议：`{task_id}_{chr}_{chromStart}_{chromEnd}_{strand}_seg{段序号}`；无峰行不产生。 |
| `chr`, `start`, `end`, `strand` | 来自元数据 `df` 的 `chr`, `chromStart`, `chromEnd`, `strand`（或 Tier B 重截后的窗口坐标，需在列注释中区分）。 |
| `peak_len` | 窗内 `find_peaks` 掩码为 1 的连续段长度（bp 数）。 |
| `peak_max_signal` | 该段内 `Y` 的最大值；或全窗 `max(Y)` 若你改为以窗为单位——须在附录固定一种。 |
| `peak_sum_signal` | 该段内 `Y` 之和。 |
| `mean_phyloP_core` | Tier A：该 peak 段上 `mean(X[...,4])`；Tier B：外扩后 bigWig 均值。 |
| `mean_phyloP_flank` | 窗内 flank 定义下 `X[...,4]` 的均值；缺失策略单独记录。 |
| `mean_phyloP_matched_bg` | 匹配到的 non-peak 区间上 PhyloP 均值（多对照可取 mean of means）。 |
| `gc_content` | 候选区间上 `(G+C)/长度`，碱基由 `argmax` one-hot 解码。 |
| `region_type` | 可选：注释 overlap 主类型；无注释则填 `NA`。 |

## 14. 最终图建议与论文式概括

- **violin/box plot**：peak vs matched non-peak 的 mean PhyloP（可跨 task 聚合或分面）。  
- **summit-centered metaplot**：以 `argmax(Y)` 为中心，**在 Tier A 允许范围内**取相对偏移的平均 PhyloP；若需 **center ±25 nt** 且窗缘不足，采用 Tier B 重截或仅分析 summit 距边缘 ≥25 nt 的子集。  
- **heatmap**：每行一个 task，颜色为 ΔphyloP。  

**一句论文式概括**

> Observed binding peaks showed higher conservation scores than matched non-peak regions, with the strongest enrichment near peak centers, supporting the biological relevance of the conservation channel.

### 15.1 本目录已实现代码（Tier A）

默认行为：test 染色体 1/8/15；`find_peaks` 默认 **sum 阈值 4**；可选 `--no-bed` 关闭 BED 子集；`--sum-threshold` 做敏感性分析；输出 `peak_table.csv`、`task_summary.csv`、跨 task JSON 与图。并行：`run_exp1.py` 默认 **约 140 个进程池 worker**（整段 `ex.map` 期间常驻复用；不超过 task 数），`EXP1_WORKERS` 或 `--workers` 可改；`--threads-per-worker` 控制每进程 BLAS 线程（默认 1，与 140 路并行匹配）。

### 15.2 通用工具链

- **Tier A**：`pandas`, `numpy`, `h5py`, `scipy.stats`；`tables`（PyTables）读 pandas HDF。  
- **Tier B**：`pysam`, `pyBigWig`；基因组 FASTA 默认路径与 [`图/figure4/figure4_locus_utils.py`](/data/CARBON_PROJECT/图/figure4/figure4_locus_utils.py) 中 `DEFAULT_GENOME_FA` 一致。  
- **bedtools**：若在 BED 层面扩 flank 再取 bigWig，可用 `bedtools slop`；Tier A 不必需。  
- **匹配**：本实现采用窗内滑动等长非峰窗口 + 多维距离打分；亦可用 `pandas.merge_asof` 等替代。  
- **检验**：`scipy.stats.wilcoxon`；可选 `statsmodels` Logit。  
- **作图**：`matplotlib` / `seaborn`。  

**仓库内可复用参考**：[`图/figure4/figure4_locus_utils.py`](/data/CARBON_PROJECT/图/figure4/figure4_locus_utils.py) 中 `read_test_bed_keys` 与 BED 路径约定；peak 语义与 [`MARCP/MARCP/utils/functions.py`](/data/CARBON_PROJECT/MARCP/MARCP/utils/functions.py) 中 `find_peaks` 对齐（本包 `exp1/peaks.py` 已独立实现相同逻辑）。
